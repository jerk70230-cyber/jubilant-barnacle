# Procedural FPS MVP

Отдельная FPS-сцена для бесконечной цепочки процедурных комнат. Исходная `SampleScene`, старый изометрический контроллер и редактор строительства тайлов не заменяются.

## Создание сцены

1. Импортировать файлы из этого патча в существующий Unity-проект поверх одноимённых файлов.
2. Дождаться окончания компиляции.
3. В Unity открыть **Tools → Cold Car → Build Procedural FPS MVP Scene**.
4. Unity создаст и сохранит `Assets/Scenes/ProceduralFPS_MVP.unity`, добавит её в Build Settings и откроет.
5. Нажать **Play**.

Сцена генерирует стартовую сейв-комнату автоматически. От неё будет ровно одна первая дверь.

## Управление

- `WASD` — движение.
- `Mouse` — осмотр.
- `Left Shift` — бег.
- `E` или ЛКМ по двери — открыть.
- `Esc` — освободить курсор; ЛКМ — снова захватить.
- `F9` — включить/выключить PS1-фильтр.

У игрока нет визуальной модели: только `CharacterController` и камера. При ходьбе камера слегка покачивается, при беге эффект сильнее. Звуки дыхания, ветра и шагов подключаются из исходных ассетов проекта через `AmbientAudioController`.

## Как устроена генерация

- При старте строится фиксированная сейв-комната и заранее рассчитывается план комнаты за её дверью.
- План комнаты хранит seed, размеры, текстуры, входную сторону и 1–5 выходных дверей. На этом этапе меши и игровые объекты следующей комнаты ещё не создаются.
- При открытии двери по готовому плану создаются пол, потолок, стены, коллайдеры, зона укрытия и выходные двери следующей комнаты.
- Когда игрок действительно проходит порог, использованная дверь переносится в новую комнату, закрывается и блокируется. Старая комната выгружается вместе со своими мешами и коллайдерами.
- У каждой новой выходной двери уже рассчитан собственный план следующей комнаты. Одновременно остаются загружены только текущая комната и одна открытая комната назначения.

Размеры помещений, количество выходов (1–5), расположение дверей и выбор текстур задаются в `ProceduralRoomManager`.

## Что сохранено из проекта

- `Ps1Filter` и исходный `PS1Post.shader`.
- `FogOfWarController`, `FogOfWarOverlay` и `TileSurface`: туман войны использует направление FPS-камеры и реальные коллайдеры стен.
- `IndoorShelterZone`: комнаты гасят ветер и участвуют в indoor-reveal тумана.
- `AmbientAudioController`: исходные дыхание, ветер и случайные звуки шагов.
- Исходные текстуры пола/стен; старый `SnowTilemapData` и редактор строительства остаются нетронутыми.

## Основные файлы

- `Scripts/Procedural/ProceduralRoomManager.cs` — планирование, построение, переход и выгрузка комнат.
- `Scripts/Procedural/OneWayProceduralDoor.cs` — анимация двери и блокировка обратного прохода.
- `Scripts/Procedural/ProceduralDoorwayTrigger.cs` — фиксация пересечения порога.
- `Scripts/Procedural/ProceduralFirstPersonController.cs` — FPS-управление, шаги и тряска камеры.
- `Editor/ProceduralFPSSceneSetup.cs` — создание отдельной сцены и подключение исходных ассетов.

## Ограничение текущего MVP

Переход намеренно линейный: открыть можно только одну дверь за раз. Пока игрок не пересёк открытую дверь, текущая комната остаётся загруженной; после пересечения предыдущая комната уничтожается. Это сохраняет однонаправленность и не позволяет накапливать историю комнат в памяти.


## Forest room

`ForestRoomGenerator` добавлен на объект `Procedural World` рядом с `ProceduralRoomManager`. Лес появляется как отдельный тип процедурной комнаты. Его линейные размеры по умолчанию составляют примерно 31.5–48 м (в 3 раза больше прежнего диапазона открытых комнат 10.5–16 м).

В Inspector доступны три списка префабов: `Tree Prefabs`, `Bush Prefabs` и `Mushroom Prefabs`. В переданном архиве есть PNG-референсы ели/сосны, но нет готовых игровых 3D-префабов этих объектов. Поэтому пустые списки автоматически используют встроенные low-poly меши-заполнители; когда появятся настоящие модели, их достаточно добавить в соответствующие массивы.

При каждом seed комнаты отдельно выбираются плотность кустов и грибов, количество объектов и профиль распределения моделей: иногда почти один вид дерева, иногда доминирующий вид с редкими примесями, иногда более равномерная смесь. Количество объектов масштабируется по площади комнаты относительно `Vegetation Reference Area`, поэтому большие лесные зоны не выглядят пустее маленьких. Все позиции детерминированы seed комнаты. Вокруг входной и выходных дверей оставляются свободные зоны.

Земля — единый сеточный меш с плавными низкоамплитудными шумовыми неровностями и одним `MeshCollider`. По границе стоят только невидимые коллайдеры, с дверными проёмами; видимых боковых стен нет. Растительность создаётся один раз при построении комнаты, использует общие fallback-меши и общие материалы. Встроенные модели используют общие Mesh/Material с включённым `enableInstancing`; Unity сможет использовать GPU Instancing там, где это допускает выбранный SRP-путь. Static Batching выключен по умолчанию, но может быть включён для подходящих пользовательских префабов. Тени по умолчанию отбрасывают только деревья; кусты и грибы продолжают принимать тени, но не создают собственные shadow casters.

Для настройки плотности используйте `minimum/maximum Trees`, `minimum/maximum Bushes`, `minimum/maximum Mushroom Groups`, `Vegetation Reference Area`, `Bush Room Presence Chance`, `Mushroom Room Presence Chance` и `Forest Room Chance`. Для рельефа — `Large/Small Bump Amplitude`, частоты шума и `Terrain Grid Resolution`. Отдельные переключатели управляют тенями деревьев/кустов/грибов и Static Batching.

После импорта проверьте лес в Play Mode: фактическое число успешно размещённых объектов и seed выводятся в Console с префиксом `[Forest]`. Для пользовательских префабов можно отдельно включить `Use Runtime Static Batching`, если их материалы не используют GPU Instancing.


Атмосфера леса: при входе включаются процедурный дневной Skybox, Directional Light с мягкими тенями и лёгкий зелёно-серый Exponential Fog. При возврате в обычную комнату менеджер восстанавливает настройки ночного освещения. Это обычный дистанционный туман Unity, а не полноценное объёмное рассеивание луча фонаря; настоящий volumetric beam потребует отдельного URP-решения и должен отдельно проверяться по производительности.
